# 사전·사후 설문 초안: AI 결과물에 대한 태도와 검토 습관 (5점 척도)

> **초안 상태**: 연구자가 수정·확정하기 전의 문항 제안입니다. 연구 계획서(`docs/research-plan.md`) 5.1절의 개념 정의에 맞춰 구성했습니다. 이 설문은 **자기보고**이므로 행동 증거(워크시트, 이벤트 기록)와 함께 해석해야 합니다.

## 1. 구성과 운영

| 항목 | 내용 |
|---|---|
| 대상 | 컴퓨터 동아리 중1~3 (연구 동의 및 보완 동의 회수 학생) |
| 시점 | **사전**: 1차시 시작 전 / **사후**: 3차시 종료 후 |
| 형식 | Google 설문. 이름·학번 대신 **연구용 코드**(학년이 드러나는 코드)를 입력 |
| 시간 | 약 5~7분 (객관식 15문항 + 사후 서술 3문항) |
| 척도 | ① 전혀 그렇지 않다 ② 그렇지 않다 ③ 보통이다 ④ 그렇다 ⑤ 매우 그렇다 |
| 사전·사후 문항 | 척도 문항(A~D)은 **사전·사후 동일**해야 변화를 볼 수 있음. 서술 문항은 사후에만 |

## 2. 측정 개념과 연구 질문 연결

| 영역 | 측정하려는 것 | 5.1절 정의와의 관계 | 연결 RQ |
|---|---|---|---|
| A. AI 답 수용 경향 | 검증·이해 없이 AI 답을 그대로 쓰려는 경향 | 인지적 외주화(수용 경향) | RQ1 |
| B. 검토 습관 | AI 결과를 예측·실행·원인 탐색하려는 습관 | 비판적 검토 | RQ2 |
| C. 이해·자기효능 | 자기 코드를 설명하고 스스로 문제를 찾을 수 있다는 인식 | 이해(자기설명) | RQ1·RQ2 |
| D. AI 신뢰 판단 | AI가 틀릴 수 있다는 인식과 확인의 필요성 | 비판적 검토의 인식적 기반 | RQ2·RQ3 |

## 3. 안내문 (설문 첫 화면)

> 이 설문은 **성적과 관계없고**, 정답이 없습니다. 선생님도 학생 이름이 아니라 **연구 코드**로만 결과를 봅니다. 평소 AI(예: 챗봇, 코딩 도우미)를 쓸 때를 떠올려서 솔직하게 답해 주세요. AI를 써 본 적이 없다면, "써 본다면 어떨지"를 생각해서 답해 주세요.

## 4. 문항

### 0. 기본 정보 (사전·사후 공통)
| # | 문항 | 응답 형식 |
|---|---|---|
| 0-1 | 연구 코드를 입력해 주세요. (예: G1-01) | 단답 |
| 0-2 | 평소 AI(챗봇, 코딩 도우미 등)를 얼마나 자주 쓰나요? | 거의 안 씀 / 한 달에 몇 번 / 일주일에 몇 번 / 거의 매일 |
| 0-3 | 코딩(파이썬, 아두이노 등)에서 AI의 도움을 받은 적이 있나요? | 없다 / 한두 번 / 여러 번 |

0-2, 0-3은 **기준선 맥락**(평소 AI 사용 정도)을 확인하는 문항으로, 변화 분석에서 사용 정도에 따라 해석을 나누는 데 씁니다.

### A. AI 답 수용 경향 (점수가 높을수록 수용 경향이 큼)
| # | 문항 |
|---|---|
| A1 | 코딩 문제가 막히면, 내가 먼저 생각해 보기보다 AI에게 답을 물어보고 싶다. |
| A2 | AI가 준 코드가 그럴듯해 보이면 실행해 보지 않고 그대로 쓸 것 같다. |
| A3 | AI가 준 코드가 잘 돌아가기만 하면, 왜 그렇게 동작하는지 몰라도 괜찮다고 생각한다. |
| A4 | AI가 답을 알려 주면, 내가 직접 고민하는 시간이 줄어든다. |

### B. 검토 습관 (점수가 높을수록 검토 습관이 강함)
| # | 문항 |
|---|---|
| B1 | AI가 준 코드를 쓰기 전에, 어떻게 동작할지 먼저 예상해 본다. |
| B2 | AI가 준 코드는 직접 실행해서 결과를 확인한 뒤에 사용한다. |
| B3 | AI가 준 코드의 결과가 내 예상과 다르면, 어디가 문제인지 찾아본다. |
| B4 | AI의 답이 틀렸다고 생각하면, 이유를 들어서 설명할 수 있다. |

### C. 이해·자기효능
| # | 문항 |
|---|---|
| C1 | 내가 만든 코드가 어떻게 동작하는지 친구에게 설명할 수 있다. |
| C2 | 오류가 나면 AI의 도움 없이도 원인을 찾아볼 수 있다. |
| C3 | 부품의 연결(회로)과 코드가 어떻게 이어지는지 이해하고 있다. |

### D. AI 신뢰 판단
| # | 문항 |
|---|---|
| D1 | AI가 알려 준 코드는 대체로 맞다고 생각한다. |
| D2 | AI도 틀린 코드를 줄 수 있다고 생각한다. |
| D3 | 실제 장치나 실행 결과로 확인하기 전에는, AI의 코드가 맞는지 알 수 없다고 생각한다. |

### E. 서술 (사후에만)
| # | 문항 |
|---|---|
| E1 | 이번 활동에서 AI가 준 코드를 확인해 보며 새로 알게 된 점은 무엇인가요? |
| E2 | 앞으로 AI가 준 코드를 받으면 어떻게 할 것 같나요? 달라진 점이 있다면 적어 주세요. |
| E3 | 활동에서 어려웠던 점이나 바라는 점이 있다면 적어 주세요. |

## 5. 채점과 해석 방법

- **영역 점수**: 영역별 문항 평균(A, B, C, D). D는 D1을 "과신" 방향으로 보고 D2·D3과 방향이 다르므로, D1은 **역채점(6−응답)**하여 "AI 판단의 신중함" 점수로 합산하는 안을 권합니다 `[연구자 확정]`.
- **변화 보기**: 사전과 사후의 영역 평균 차이를 **학생별로** 보고, 인원이 적으므로 통계 검정보다는 **분포와 사례 중심**으로 기술합니다(비교 집단 없음).
- **기대 방향(가설이 아니라 해석 기준)**: A는 낮아지고 B·C·D는 높아지는지 보되, 오르내림이 곧 활동의 효과라고 단정하지 않습니다.
- **함께 해석할 자료**: 워크시트 루브릭 점수, 자기설명, 이벤트 기록. 설문과 행동 증거가 어긋나면 그 자체가 분석 대상입니다.
- **학년 변수**: 0-1의 연구 코드에서 학년을 구분해 기록합니다.

## 6. 타당도·신뢰도 점검 (권장)

- **내용 타당도**: 정보 교과 교사나 연구 동료 2~3명에게 문항이 각 개념에 맞는지, 중학생이 이해할 수 있는지 검토받습니다.
- **문항 이해도**: 파일럿에서 학생 몇 명에게 "이 문장을 어떻게 이해했는지" 물어봅니다. 특히 A2, B4, D3는 중1에게 어려울 수 있습니다.
- **신뢰도**: 영역당 문항 수가 3~4개라 인원이 적으면 Cronbach's α는 참고용입니다. 낮게 나오면 문항을 늘리기보다 표현을 다듬습니다.
- **응답 편향**: 모든 문항이 같은 방향이면 "그렇다"로 몰릴 수 있습니다. A영역은 "수용 경향", B·C영역은 "검토·이해"로 방향이 서로 다르게 섞여 있는 구성이지만, 필요하면 각 영역에 반대 방향 문항을 하나씩 추가하세요.
- **사회적 바람직성**: "AI를 안 믿고 검증한다"는 쪽으로 답하는 것이 바람직해 보입니다. 안내문의 "성적 무관·정답 없음·연구 코드" 문구를 그대로 두세요.

## 7. 연구자 결정이 필요한 사항

1. D1의 역채점 여부와 영역 점수 산출 방식
2. 문항 수 조정(현재 14문항 + 기본 정보 2문항, 서술 3문항)
3. 사전·사후 외에 중간 점검(2차시 후)이 필요한지(권장하지 않음: 3차시가 짧음)
4. 용어 확인: "AI", "코딩 도우미" 등 학생에게 익숙한 표현으로 바꿀지
5. 선행 연구의 기존 척도를 참고·인용할 부분이 있는지(이 초안은 이 연구에 맞게 새로 작성)
