# AI 제안 카드용 프롬프트 템플릿 (교사 수집용)

> **초안 상태**: 연구 계획서(`docs/research-plan.md`)의 AI 제안 카드(m3 결함 1장, m4 결함 1장, m4 무결함 1장)를 만들기 위해, 교사가 생성형 AI에게 직접 물어서 **실제 출력**을 모으는 절차와 프롬프트입니다. 카드의 출처가 "AI가 실제로 준 답"이어야 연구의 현실성이 유지됩니다.

## 1. 수집 원칙

1. **같은 프롬프트는 같은 조건으로**: 모델 이름·버전, 날짜, 프롬프트 전문, 시도 횟수를 기록합니다(5절 기록표).
2. **결함을 유도하는 말을 넣지 않습니다**: "버그가 있는 코드를 줘"라고 하면 자연스러운 AI 출력이 아니라 심어 둔 결함이 됩니다. 학생이 실제로 쓸 법한 질문을 그대로 씁니다.
3. **같은 프롬프트로 여러 번(권장 5회) 새 대화에서 시도**하고, 결함이 자연스럽게 나온 출력이 있으면 그것을 씁니다.
4. **자연 출력에 결함이 없으면** 아래 3절의 "최소 수정"을 적용하되, 무엇을 어떻게 바꿨는지 수정 기록에 남깁니다. (카드에는 "AI 출력"이지만 연구 보고서에는 "일부 교사 수정"이라고 밝힙니다.)
5. **무결함 카드(m4)는 수정 없이** 실제 출력 그대로 쓰되, 시뮬레이터에서 실행해 정말 통과하는지 먼저 확인합니다.
6. 학생 이름·학급 등 개인정보는 프롬프트에 넣지 않습니다.

## 2. 프롬프트

### P-m3 (2차시, 결함 카드 후보)

```
라즈베리파이 피코에서 MicroPython으로 코딩하고 있어.
GP14 핀에 버튼이 연결되어 있고, 버튼의 다른 쪽은 GND에 연결되어 있어.
GP15 핀에는 LED가 연결되어 있어.
버튼을 누르고 있는 동안만 LED가 켜지고, 버튼을 떼면 꺼지게 하는 코드를 알려줘.
```

- 기대하는 결함 후보: 풀 설정 불일치(GND 버튼에 `Pin.PULL_DOWN` 사용, 또는 풀 설정 누락) → "눌러도 LED가 안 켜짐". 시뮬레이터에서 안내 문구가 뜨는 것을 확인했습니다.
- 주의: 최신 AI는 이 질문에 `PULL_UP`을 정확히 쓰는 경우가 많습니다. 그러면 결함이 자연스럽게 나오지 않은 것이므로 3절을 적용합니다.

### P-m4 (3차시, 결함 카드 후보 + 무결함 카드 후보)

```
라즈베리파이 피코에서 MicroPython으로 코딩하고 있어.
가변저항(포텐셔미터) 가운데 단자를 GP26 핀에 연결했고, 양쪽 끝은 3.3V와 GND에 연결했어.
가변저항 값을 0.2초마다 읽어서 출력하는 코드를 알려줘.
```

- 이 프롬프트로 나온 출력은 대부분 **정상**일 것이므로 **무결함 카드**의 후보입니다. 시뮬레이터에서 값이 바뀌며 출력되는지 확인한 뒤 채택합니다.
- 결함 카드는 자연 출력에서 얻기 어렵습니다. 아래 3절의 최소 수정(핀 번호)을 쓰거나, 학생이 흔히 하는 오해를 담은 변형 질문으로 시도합니다.

### P-m4-변형 (결함 유도가 아닌 "현실적 모호함")

```
라즈베리파이 피코에서 가변저항 값을 읽고 싶어. 아날로그 값을 0.2초마다 출력하는 MicroPython 코드 알려줘.
```

- 핀 번호를 알려 주지 않으면 AI가 임의 핀을 고를 수 있습니다. ADC가 아닌 핀(예: GP15)을 고르면 시뮬레이터에서 `ValueError: Pin doesn't have ADC capabilities`가 납니다. 다만 대부분의 AI는 GP26을 고르는 경향이 있어 보장되지 않습니다.

## 3. 자연 출력에 결함이 없을 때: 최소 수정과 기록

| 카드 | 최소 수정 | 학생이 실행했을 때 보이는 현상(시뮬레이터에서 확인) |
|---|---|---|
| m3 결함 | `Pin(14, Pin.IN, Pin.PULL_UP)` → `Pin(14, Pin.IN, Pin.PULL_DOWN)` 한 줄만 변경 | 풀 설정 불일치 안내가 뜸. **버튼을 눌렀을 때 LED가 안 켜지는지는 교사가 직접 확인 필요(미검증)** |
| m4 결함 | `ADC(26)` → `ADC(Pin(15))` 한 곳만 변경 | `ValueError: Pin doesn't have ADC capabilities` + 한국어 도움말 |
| m4 무결함 | 수정 없음 | 값이 0~65535로 출력되고 손잡이를 움직이면 변함 |

- 수정은 **한 곳, 한 줄**로 제한합니다. 여러 곳을 바꾸면 "결함 하나를 찾는" 활동이 아니라 퍼즐이 됩니다.
- 수정한 사실은 카드 뒷면이 아니라 **연구자 기록**(5절)에 남깁니다.

## 4. 수집 후 교사 확인 체크리스트

- [ ] 각 후보 코드를 시뮬레이터(또는 실물)에서 직접 실행해, 카드에 적을 "증상"을 눈으로 확인했다.
- [ ] 결함 카드의 결함이 **하나뿐**이고, 학생이 실행·관찰로 발견할 수 있다(코드만 읽어서 알 수 있는 결함은 제외).
- [ ] 무결함 카드가 실제로 미션을 통과한다.
- [ ] AI 출력에 설명 문장이 길게 붙어 있으면, 코드 + 짧은 설명 정도로 줄이되 **결함·정상 여부를 암시하는 문장은 삭제**한다(삭제 사실도 기록).
- [ ] 같은 학년·같은 시간에 모든 학생이 같은 카드를 받도록 준비했다.
- [ ] 카드에 "이 코드는 AI가 제안했습니다"만 적고, 맞다/틀리다는 어디에도 쓰지 않았다.

## 6. 알아 둘 점

- 이 프롬프트들은 **초안**입니다. AI 모델과 날짜에 따라 출력이 달라지므로, 파일럿 전에 한 번 더 수집해 카드를 확정하세요.
- 수업에서 학생에게 AI 도구를 직접 쓰게 하지 않는다는 연구 설계(교사가 AI 제안을 제공)에 맞춘 절차입니다.
- 결함이 심어진 카드를 쓰는 연구라는 점은 활동 후 학생에게 **사후 설명**하는 것을 권장합니다(계획서 8절 윤리 부분 참고).
- 코드는 수정하지 않았고, 이 문서는 커밋하지 않았습니다.
